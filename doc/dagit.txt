1. Introduction                                                  *dagit-intro*

dagit shows `git log` in a horizontal split. Each commit is one row:

    > graph  hash HEAD branch subject    tag    author    date time

`>` marks the highlighted row, in addition to the |hl-CursorLine|
background. The history opens on the checked-out commit. When that
commit is not in the loaded log, the first row is highlighted.
Other rows leave that cell blank so the graph stays aligned.
The row for the commit HEAD points at is bold. Its decoration is
`HEAD branch`. Each branch name is a badge in that commit's lane
color, with the letters cut out of the history background, the same
way `HEAD` is drawn. A plain space sits between badges. A detached
HEAD is the badge alone. Tags sit on the right, ahead of the author.
Several tags on one commit collapse
to one label. The hash uses |DagitHash|.
A commit that is not on any remote uses |DagitHashLocal|.
A local branch whose upstream is gone shows `(upstream gone)` after
the branch name, in |DagitUpstreamGone|.
`<CR>` toggles a block under the highlighted commit. The text is
indented. More than five changed files start the block with a count,
such as `3 added, 1 modified, 2 deleted`. The commit description,
when the commit has one, comes next. Each changed file follows on
its own line: `M`, `A`, `D`, or `R`, then the path. A rename
or a copy shows the old path, then the new path. The graph lanes
continue through that block. `j` and `k` move through the lines.
Press `<CR>` again to hide it. `z` toggles the block as well.
`Z` hides every open block.

A filter line stays at the top of the window:

    [all]  local  remote  head

`<Tab>` selects the next filter. `<S-Tab>` selects the previous one.
Brackets mark the active name. A new window starts on |dagit-filter|
(default `all`). `all` is the loaded log. `local` shows commits
reachable from a local branch or HEAD. `remote` shows commits
reachable from a remote-tracking branch. `head` shows commits
reachable from the checked-out branch. The line stays put while
the log scrolls. An open window keeps the filter it already has.

The caret is hidden. The window background follows the Snacks explorer
(`SnacksPickerList`, then `SnacksPicker`, then |hl-NormalFloat|).

A commit in the middle of a lane is a circle with a line through it, so a
straight history stays connected. A tip has the line below the circle, and
a root has the line above it. When another branch leaves that same merge,
the merged parent stays on the node. The other branch joins the line above
the node. On a merge commit, the cell beside the commit is an arrow
pointing at it. A parent lane that continues through that row draws a
junction, so the arrow meets the line. The rest of that line stays
plain. Where a branch is created, the meeting lines stay plain.
Ghostty, Kitty, and Contour paint the default
glyphs to the cell edge. Other terminals use Nerd Font circles. Override
|dagit-symbols| to draw plain characters instead. A branch that is not
local uses the muted lane color |DagitGraph1Muted| through
|DagitGraph8Muted|: the same lane color, faded toward the background.
From the first commit that is also on a local branch, that lane uses
the full color. The hash, subject, decoration, tag, author, and date
on a commit that is not local use the same fade (|DagitTextMuted| for
the subject). The description and file lines under that commit use
the Muted copy of |DagitBody| and the file groups.

The graph, subject, and metadata colors are linked to your colorscheme.
Override the |dagit-highlights| groups to change them.

dagit works without calling |dagit.setup()|. The plugin file only creates
|:Dagit| and the |dagit-mappings| `<Plug>` maps.

Requirements: Neovim 0.10+, Git.

==============================================================================
2. Commands                                                   *dagit-commands*

                                                                    *:Dagit*
:Dagit [subcommand] [args]

    Open the history when no subcommand is given. Subcommands:

    :Dagit log [git-log-args]   Open the history. Arguments replace
                                |dagit-log_args| for this call.
                                Example: `:Dagit log main`
    :Dagit refresh              Reload the open history
    :Dagit copy                 Copy the hash under the cursor
    :Dagit close                Close the history window

    Tab completion lists the subcommands, and ref names after `:Dagit log`.

The repository is the one that contains the current file, or the working
directory when the current buffer has no file.

3. Mappings                                                   *dagit-mappings*

Buffer-local maps in the history window:

    <C-o>     Copy the full hash of the cursor row     *<Plug>(DagitCopyHash)*
    r         Reload the history                      *<Plug>(DagitRefresh)*
    q         Close the window                        *<Plug>(DagitClose)*
    <CR>      Show or hide the description and files  *<Plug>(DagitExpand)*
    z         Show or hide the description and files  *<Plug>(DagitShow)*
    Z         Hide every expanded commit              *<Plug>(DagitCollapse)*
    <Tab>     Next commit filter                     *<Plug>(DagitFilterNext)*
    <S-Tab>   Previous commit filter                 *<Plug>(DagitFilterPrev)*

`<CR>` runs |dagit-on_select| when that callback is set and
|dagit-keymaps| `expand` is not `<CR>`.

<C-o> is local to the history buffer. The jump-list mapping is left alone
in every other window.

`<Tab>` and `<S-Tab>` are local to the history buffer. In a terminal
`<Tab>` is the same key as `<C-i>`.

`<Plug>` maps, for your own keys:

    vim.keymap.set("n", "<leader>gl", "<Plug>(DagitOpen)")
    vim.keymap.set("n", "<leader>gy", "<Plug>(DagitCopyHash)")

                                                         *<Plug>(DagitOpen)*

Set |dagit-keymaps| entries to `false` to skip a default buffer map. A
buffer-local map created from a |FileType| `dagit` autocommand is kept.

4. Configuration                                                *dagit-config*

Put overrides in `vim.g.dagit` or pass them to |dagit.setup()|. `setup()`
wins when both are set. Both accept a table or a function that returns one.

`setup()` does not open a window and does not create maps.

    require("dagit").setup({
        height = 18,
        date_format = "relative",
    })

    vim.g.dagit = {
        icons = { enabled = false },
    }

The resolved values:

                                                         *dagit-height*
height              number (default 16)
                    Rows in the split. A number between 0 and 1 is a
                    fraction of the screen.

                                                         *dagit-split*
split               "bottom" or "top" (default "bottom")

                                                         *dagit-filter*
filter              "all", "local", "remote", or "head"
                    (default "all")
                    Filter selected when a history window opens.
                    `all` is the loaded log. `local` keeps commits
                    reachable from a local branch or HEAD. `remote`
                    keeps commits reachable from a remote-tracking
                    branch. `head` keeps commits reachable from the
                    checked-out branch. Focusing an open window
                    leaves its filter alone.

                                                         *dagit-max_count*
max_count           integer (default 256)
                    Maximum commits to load.

                                                         *dagit-log_args*
log_args            string[] (default { "--all" })
                    Extra arguments for `git log`. The list is replaced,
                    not appended, when you override it.
                    `--date-order` is added unless you pass `--date-order`,
                    `--topo-order`, or `--author-date-order` yourself.
                    `--all` skips `refs/stash`. Pass `refs/stash`
                    to include stashes.

                                                         *dagit-date_format*
date_format         string (default "%d %b %H:%M")
                    An |os.date()| format, or "relative".
                    The default prints the day, month, and
                    time. A commit from another year also
                    prints that year. The current year is
                    left off. A format with no clock, such
                    as "%d %b", still gets "HH:MM" after
                    the date. A format that already prints
                    a year is left as written. "relative"
                    uses ages such as "2h ago", and a full
                    date with time after two weeks.

                                                      *dagit-author_max_width*
author_max_width    integer (default 22)

                                                         *dagit-ref_max_width*
ref_max_width       integer (default 30)
                    Maximum display width of the
                    `HEAD branch` decoration, including
                    the badges, the space between them,
                    and `(upstream gone)`, and of the tag
                    on the right. Head and local branches
                    are kept ahead of remotes. Names that
                    do not fit are dropped from the end,
                    then truncated. A tag is truncated to
                    this width.

                                                      *dagit-multi_tag_label*
multi_tag_label     string (default "multi tag")
                    Label used on the right when a commit has
                    more than one tag. A single tag is shown
                    by name.

                                                         *dagit-dim_merges*
dim_merges          boolean (default true)
                    Use |DagitMerge| for commits that have more than one
                    parent.

                                                         *dagit-git_cmd*
git_cmd             string (default "git")

                                                         *dagit-notify*
notify              boolean (default true)
                    Show informational messages such as "Copied <hash>".
                    Errors are still reported when this is false.

                                                         *dagit-icons*
icons.enabled       boolean (default true)
icons.head          string  Glyph for the branch pointed at by HEAD
icons.branch        string  Glyph for other local branches
icons.remote        string  Glyph for remote-tracking branches
icons.tag           string  Glyph for tags

                    The defaults are Nerd Font icons, drawn
                    before each branch name and before the
                    tag on the right. Set `enabled` to false
                    to show the name alone. `origin/HEAD` is
                    hidden because it repeats the remote's
                    default branch.

                                                         *dagit-symbols*
symbols.commit            string
                    Lone commit. Nothing connects above or below it.
symbols.commit_down       string
                    Circle with a line down to the parent.
symbols.commit_up         string
                    Circle with a line up from the child.
symbols.commit_through    string
                    Circle with a line through it.
symbols.vertical          string
symbols.horizontal        string
symbols.branch_start      string
symbols.merge_right       string
symbols.merge_left        string
symbols.join_right        string
                    Vertical lane with a bar to the right.
                    Drawn when a merge parent on the left
                    continues through the row, so the arrow
                    meets the line. Default `├`.
symbols.join_left         string
                    Vertical lane with a bar to the left.
                    Drawn when a merge parent on the right
                    continues through the row. Default `┤`.
symbols.arrow_right       string
                    Arrow in the cell left of a merge commit.
                    The parent lane is on the left.
                    Default `⊳`. One cell wide.
symbols.arrow_left        string
                    Arrow in the cell right of a merge commit.
                    The parent lane is on the right.
                    Default `⊲`. One cell wide.
symbols.diagonal_right    string
                    Parent lane sloping down and to the right.
                    Default `╲`.
symbols.diagonal_left     string
                    Parent lane sloping down and to the left.
                    Default `╱`.

                    The four commit glyphs must be the same display width.
                    On Ghostty, Kitty, and Contour the defaults are the
                    branch-drawing glyphs those terminals paint to the cell
                    edge, so a straight lane stays continuous. Elsewhere the
                    defaults are Nerd Font circles and box-drawing lines.
                    Corners and junctions are box-drawing angles (`┐`, `┘`,
                    `└`, `├`, `┤`). The branch-drawing corners are quarter
                    circles, so the bar leaves the midline. The arrows are
                    `⊳` and `⊲`, one cell each. A glyph wider than one cell
                    is drawn as `>` or `<`. A wide junction is drawn as the
                    plain vertical.
                    Setting `symbols` keeps your glyphs on every terminal.
                    The cursor row is the highlight; the glyph stays in
                    place so the line through the circle is not covered.

                                                         *dagit-keymaps*
keymaps.copy_hash   string or false (default "<C-o>")
keymaps.close        string or false (default "q")
keymaps.refresh     string or false (default "r")
keymaps.expand      string or false (default "<CR>")
                    Show or hide the description and the
                    files under the cursor commit.
keymaps.show        string or false (default "z")
                    Show or hide that block. Same action as
                    `keymaps.expand`.
keymaps.collapse    string or false (default "Z")
                    Hide the block under every commit.
keymaps.filter_next string or false (default "<Tab>")
                    Select the next commit filter:
                    all, local, remote, head.
keymaps.filter_prev string or false (default "<S-Tab>")
                    Select the previous commit filter.

                                                         *dagit-on_select*
on_select           fun(commit: dagit.Commit) or nil
                    Called for `<CR>` when `keymaps.expand` is
                    not `<CR>`. Use it for another action, such
                    as opening a diff. The commit table
                    has `hash`, `parents`, `author`, `timestamp`, `subject`,
                    `refs`, `local_only`, `remote_only`, `on_local`,
                    `on_remote`, and `on_head`. Each ref has
                    `name`, `kind` (`head`, `branch`, `remote`, or `tag`),
                    and `upstream_gone`. That is true when the local branch
                    tracks a remote ref that no longer exists.
                    `local_only` means no remote-tracking ref reaches the
                    commit. `remote_only` means a remote-tracking ref
                    reaches it and no local branch or HEAD does.
                    `on_head` means the checked-out branch reaches it.

Invalid configuration is ignored. dagit keeps working with the defaults
and reports the problem from |:checkhealth| and |vim.notify()|.

5. Highlight groups                                         *dagit-highlights*

These groups link to the active colorscheme. Defining one yourself, or in
a colorscheme, replaces the link.

    DagitGraph1 .. DagitGraph8    One color per graph lane.
    DagitGraph1Rev .. DagitGraph8Rev
                                  Branch and remote names on that
                                  lane. The lane color fills the
                                  cells. The letters use the history
                                  background. A space on each side
                                  makes the name a badge.
    DagitGraph1Muted .. DagitGraph8Muted
                                  That lane, faded toward the
                                  background, for a branch that is
                                  not local. Defining the group
                                  yourself keeps your color.
    DagitGraph1MutedRev .. DagitGraph8MutedRev
                                  The same badge, filled with the
                                  muted lane color.
    DagitTextMuted                Subject on a commit that is
                                  not local. The hash, decoration,
                                  tag, author, and date on that
                                  row use the Muted copy of their
                                  usual group.
    DagitHash                     Abbreviated commit hash    (Label)
    DagitHashLocal                Hash of a commit that is not
                                  on any remote   (DiagnosticWarn)
    DagitUpstreamGone             "(upstream gone)" after a
                                  local branch whose upstream
                                  ref is missing
                                  (DiagnosticError)
    DagitDecor                    Delimiter                      (Delimiter)
    DagitNormal                   History window background.
                                  SnacksPickerList, then
                                  SnacksPicker, then NormalFloat.
    DagitHeadMark                 The word HEAD, with a space
                                  on each side so the fill reads
                                  as a badge. A plain space
                                  separates it from the next
                                  badge. |Special| fills the
                                  cells. The letters use the
                                  history background.
    DagitHead                     Bold text. The ">" on the
                                  highlighted row, the subject
                                  when that commit is HEAD and
                                  is not dimmed as a merge, and
                                  the active filter name.
    DagitFilter                   Inactive names on the filter
                                  line.                      (Comment)
    DagitCursor                   Hidden caret. blend=100.
    DagitMerge                    Merge commit subjects      (Comment)
    DagitAuthor                   Author column              (Comment)
    DagitDate                     Date and time column       (NonText)
    DagitRefTag                   Tags                       (Constant)
    DagitBody                     Commit description under
                                  an expanded row            (Comment)
    DagitFileAdded                Added file                 (DiagnosticOk)
    DagitFileModified             Modified file              (DiagnosticWarn)
    DagitFileDeleted              Deleted file               (DiagnosticError)
    DagitFileRenamed              Renamed or copied file     (DiagnosticHint)
    DagitBodyMuted                Description on a commit
                                  that is not local. File
                                  lines use the Muted copy of
                                  their status group.

The links are reapplied on |ColorScheme| only when you have not defined
the group.

6. API                                                             *dagit-api*

The Lua module is `dagit`. Modules under `dagit._core` are private.

    require("dagit").setup(opts)           *dagit.setup()*
        Store configuration. Returns the resolved config.

    require("dagit").open(opts)            *dagit.open()*
        Open or focus the history split. A new history starts on
        the checked-out commit, inside the filter from |dagit-filter|.
        opts.cwd        directory inside the repository
        opts.log_args   replaces log_args for this open
        opts.max_count  overrides max_count for this open
        opts.height     overrides height for this open

    require("dagit").refresh()             *dagit.refresh()*
    require("dagit").close()               *dagit.close()*
    require("dagit").copy_hash()           *dagit.copy_hash()*
        Copy the full hash under the cursor into the unnamed register,
        and into the `+` register when a clipboard provider exists.

    require("dagit").expand()              *dagit.expand()*
        Show or hide the description and files for the commit under
        the cursor. The description is the commit body. More than
        five changed files start with a count, such as `3 added,
        1 deleted`. Each file is a status letter (`M`, `A`, `D`,
        `R`, or `C`) and its path. A rename is `R old -> new`.
        On a commit that is not local, those lines use the same
        muted colors as the row.

    require("dagit").show()                *dagit.show()*
        Show or hide the description and files for the commit
        under the cursor. Same action as |dagit.expand()|.

    require("dagit").collapse()            *dagit.collapse()*
        Hide the description and files under every commit.

    require("dagit").filter_next()         *dagit.filter_next()*
        Select the next filter (`all`, `local`, `remote`, `head`)
        and redraw. Returns the active name, or nil when the
        history window is not focused.

    require("dagit").filter_prev()         *dagit.filter_prev()*
        Select the previous filter and redraw. Returns the same
        way as |dagit.filter_next()|.

    require("dagit").commit()              *dagit.commit()*
        The |dagit-on_select| commit under the cursor, or nil.

7. Health                                                       *dagit-health*

    :checkhealth dagit

Reports the Git executable, whether the working directory is inside a
repository, and any configuration errors.
